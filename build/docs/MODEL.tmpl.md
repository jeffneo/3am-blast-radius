# The Graph Model

Fully fictional. **{{n nodes}} nodes, {{n relationships}} relationships.** Generated by [`../build/generate.py`](../build/generate.py) from the facts in [`../build/estate.py`](../build/estate.py) into [`load.cypher`](load.cypher). The generator is seeded, so the file is identical on every run. Every figure on this page is computed from the tested results, not typed.

## Schema

```
                         (:Team {status, pager})
                          ▲        ▲        ▲
              [:OWNS]─────┘        │        └─────[:OWNED_BY]── (:Journey) ──[:REQUIRES]──┐
                 │                 │                                                      ▼
                 │        (:Component:Service)                    ┌──[:DEPENDS_ON {critical, hard, confirmed,
                 │        (:Component:Datastore) ◀────────────────┘                  source, active, first_seen, ...}]
                 ▼                 ▲
          (:Certificate) ◀─[:USES_CERT]── (:Service)
                 ▲
   (:Incident {impact, duration_minutes, reassignments}) ──[:ROOT_CAUSE]──▶ (:Component) or (:Certificate)
                                                         ──[:AFFECTED]───▶ (:Service)
                                                         ──[:ASSIGNED_TO]─▶ (:Team)
   (:Change {deployed_at, risk_review})  ──[:DEPLOYED_TO]──▶ (:Service)
   (:Runbook {last_reviewed, stale})     ──[:COVERS]──────▶ (:Component)
   (:Alert {fired_at})                   ──[:FIRED_ON]────▶ (:Component)
```

## Nodes

| Label | Count | Key | Notable properties |
|---|---|---|---|
| `:Component:Service` | {{f services}} | `name` | `tier` (1 = customer-facing critical … 3 = can wait; **null = never rated**), `lifecycle` (`active` / `deprecated`) |
| `:Component:Datastore` | {{f datastores}} | `name` | `kind`, `tier` (**declared** tier), `pagerank`, `cluster_id` |
| `:Team` | {{f teams}} | `name` | `pager` (null = nobody on call), `status` (`active` / `disbanded`), `disbanded_on` |
| `:Journey` | {{f journeys}} | `name` | `customers_per_day`, `per_hour_0300`, `per_hour_0700`, `per_hour_1200`: **attempts** at that journey (invented). A customer who logs in and then checks a balance is two attempts, so sums across journeys are not unique people |
| `:Incident` | {{f incidents}} | `id` | `severity`, `started_at`, `impact` (`degraded` / `outage`), `duration_minutes`, `customers_impacted` (**sometimes missing**), `reassignments`, `detail` |
| `:Change` | {{f changes}} | `id` | `deployed_at`, `what`, `risk_review` |
| `:Runbook` | {{f runbooks}} | `id` | `last_reviewed`, `stale` (not reviewed in 12 months) |
| `:Certificate` | {{f certificates}} | `name` | `expires_on`, `last_rotated`, `auto_renew` (**sometimes unknown**), `issuer`. **Not mentioned in the guide: see the easter egg in STORYLINE.md** |
| `:Alert` | {{f alerts}} | `id` | `fired_at`, `summary` |

Every `:Component` also carries two **precomputed GDS scores** (`pagerank`, `cluster_id`) because the target sandbox has no Graph Data Science. See below.

## The edge: what "depends on" means here

Every `DEPENDS_ON` carries:

| Property | Values | Meaning |
|---|---|---|
| `critical` | `true` / `false` / **`null`** | Hard, soft, or **never classified** |
| `source` | `both` / `observed` | In the catalog and in traces, or **seen in traces only** (undeclared) |
| `active` | boolean | Traffic seen in the last 30 days. `false` = declared, but gone quiet |
| `first_seen`, `last_seen` | dates | |
| `introduced_by` | change id or null | The change that added it, where known |
| `confirmed` | derived | `active` and `critical = true`. **Provably hard** |
| `hard` | derived | `active` and `critical` is not `false`. **Assume the worst** |

`confirmed` is the best case you can prove. `hard` is the worst case you must plan for. The queries use both, and the distance between them is the story.

## The mess, and what each kind is for

| Mess | Count | What it makes possible |
|---|---|---|
| **Unclassified dependencies** (`critical = null`) | {{f dep_unclassified}} | The best-case / worst-case range (B2b, B3b); the triage question (B2c) |
| **Undeclared dependencies** (`source = observed`) | {{f dep_undeclared}} | "Nobody declared it" (B6b). {{f dep_tracing}} are routine tracing edges; the other {{f dep_undeclared_other}} include the one that matters |
| **Inactive dependencies** | {{f dep_inactive}} | Stale links are ignored, not counted |
| **Mutual dependencies** (A calls B calls A) | {{f mutual_pairs}} pairs | Real service graphs have cycles; the bounded queries cope |
| **Disbanded teams** | {{f teams_disbanded}} teams owning {{f owned_by_disbanded}} components | Components nobody can be paged for (B4b), and a certificate owned by a team that no longer exists |
| **Unowned datastores** | {{f unowned}} | Ownership gaps |
| **Never-rated components** | {{f unrated}} | A datastore with no tier, under journeys (`UNRATED` in B5) |
| **Deprecated services** | {{f deprecated}} | Decommissioned things still on a critical path; lookalikes (`auth-proxy`, `notifications-legacy-svc`) |
| **Active team, nobody on call** | {{f teams_no_pager}} | A pager that goes nowhere |
| **Stale runbooks** | {{f runbooks_stale}} of {{f runbooks}} | "Covered" is not the same as "covered well" (B9) |
| **Incomplete incidents** | {{f incidents_without_root}} with no recorded root cause, {{f incidents_no_customers}} with no customer count | Stats that are honest about what they cover (B7, B7b) |
| **Certificates** | {{f certs_renewal_unknown}} with renewal unknown, {{f certs_manual}} renewed by hand | The easter egg, and the decoys |
| **Alerts that are noise** | {{f storm_unrelated}} of {{f storm_alerts}} tonight | Telling cause from symptom from nothing (B1b) |
| **Observability edges** | {{f dep_tracing}} | Clutter: everything reports to the tracing collector |

## The planted pattern

The cache is declared tier {{f cache_tier}}, but `customer-profile-svc` depends on it hard, and {{f journeys_worst}} of {{f journeys}} journeys sit above that service in the worst case:

```
Log in, Check a balance, Transfer money, ...  (journeys with no other route)
   └─▶ auth-gateway ─▶ entitlements-svc ─(UNCLASSIFIED)─▶ customer-profile-svc ─▶ profile-cache
Send a wire ─▶ wire-svc ─▶ sanctions-screening ─────────────────(critical)──────┘
Apply for a mortgage ─▶ loan-origination-svc ───────────────────(critical)───────┘
Update contact details ─▶ alerts-preferences-svc ───────────────(critical)───────┘
Tap to pay ─▶ card-auth-svc ─▶ fraud-scoring-svc ┈┈(soft, with fallback)┈┈▶ customer-profile-svc
```

{{f journeys_proven}} journeys are provably down. The other {{f journeys_assumed}} are down only if unclassified links turn out to be hard. *Tap to pay* survives either way.

## GDS scores, and why they are properties

The JPMC sandbox runs Neo4j 5.26 with no Graph Data Science. So `build/build.sh` computes them once, in the dev stack, and bakes them into `load.cypher` as ordinary properties:

- **`pagerank`**: PageRank over the hard dependencies, flowing from a dependent to what it needs. High means *a lot of the estate leans on this*.
- **`cluster_id`**: Louvain communities over the same edges, ignoring direction, renumbered by size (1 = largest).

The lab never says "run an algorithm". It says "this property came from one, and here's what it shows" (B10).

## Conventions

- **Time is fixed.** "Tonight" is `2026-09-30T03:07:00Z`, written into the queries, so results never depend on the clock.
- **No APOC, no `$params`, all paths bounded** (`*1..8`). Enforced by `build/verify.py`.
- **Neo4j 5.26 compatible.** Verified on 5.26 and on 2026.08 with identical results.
- **The loader is batched.** {{f rel_depends_on}} dependencies, {{f changes}} changes and the rest load in statements of at most {{f load_chunk}} rows, so no single statement is large and the whole script runs anywhere `cypher-shell` does.
